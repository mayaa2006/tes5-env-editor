# Roadmap and honest status

Legend: ✅ working and tested · 🟡 partial / limited · ❌ not implemented yet

Tested means unit tests (`npm test`) plus the Playwright run of the browser demo (`npm run test:e2e`). **Nothing has been verified yet against a real Skyrim.esm load order or in-game.** That is the most important next step.

## Status against the Creation Kit

| Feature | Status | Notes |
| --- | --- | --- |
| Read/write ESM/ESP/ESL, compressed records, localized strings | ✅ | Lossless round-trip is checked before a record can be edited. |
| Record coverage | 🟡 | Forms for quests, dialogue, characters, world objects, items, crafting, leveled lists, magic and perks (61 types). Checked with `tes5 records-check` on Skyrim.esm, Update.esm and the three DLC masters: every record of every type with a form reads and writes back byte for byte. Some forms don't cover every field yet (armor addons, factions, locations, packages, races, scenes, landscape texture layers); those fields are kept exactly as they are. **Still without a form** (shown as raw fields, kept exactly): weather, climate, image spaces, lighting templates, water, grass, load screens, sounds and music, combat styles, relationships, encounter zones, projectiles, explosions, hazards, art objects, visual effects, actor values, Story Manager nodes, and a few rarer types. New records can be created from scratch in the Items and Magic tabs (and placeable world objects in World → Objects). |
| Load order, plugins.txt, MO2 instances/profiles, BSA + loose VFS | ✅ | Real MO2 setups are untested. |
| Undo/redo, auto masters, backups, atomic saves | ✅ | |
| ITM / UDR cleaning (Quick Auto Clean) | ✅ | Safe and xEdit modes. Deleted-navmesh repair is experimental. |
| 3D viewport, Blender controls, drag & drop placement | ✅ | Outdoors, the neighbouring cells (up to 2 around) load too, with persistent references placed by position. |
| Characters in the viewport | 🟡 | Body (race skin or creature body), default outfit armor (covering the skin pieces in its slots) and head (FaceGen file, else the race's head parts), following template and leveled-list rules. Shown in the rest pose, without animation, in the world and on the character creator's Body page. Skinned meshes' UVs and normals come from the skin partition's vertex buffer. Armor addons are chosen by race; bodies and armor are blended between _0 and _1 by weight. Normal maps (tangent-space, and model-space on skin: R = X, B = Y, G = Z, measured on vanilla meshes) and specular masks are drawn; subsurface (_sk) and the game's exact skin lighting aren't. |
| Rendering fidelity | 🟡 | Diffuse textures and alpha are supported. Normal/specular maps, LOD, water, sky and weather are not. |
| Effects and markers in the viewport | 🟡 | Effect meshes (glows, webs, splashes) use their texture, colour and blend mode; mist, smoke and other particle systems aren't drawn (only a small marker), and their editor boxes are hidden. Marker shapes inside furniture and perches are hidden unless View → Marker shapes on furniture is on. Water uses a plain translucent blue. |
| Exterior terrain (LAND) | 🟡 | Heights, vertex colours and **texture layers** are shown: each cell's base and painted landscape textures (LAND BTXT/ATXT/VTXT → LTEX → TXST) are blended into one 512² picture per cell; each texture repeats 6 times per cell (an estimate, to check against the game). **Sculpting** (raise, lower, smooth, flatten) writes heights and normals; all 15,410 vanilla Skyrim.esm landscapes re-encode byte for byte, and shared edges stay identical across cells. Vertex colours aren't changed by sculpting, texture painting isn't available yet, and LOD isn't regenerated (distant terrain keeps the old shape until LOD is rebuilt with xLODGen). Only navmeshes made here are marked out of date by sculpting. |
| Navmesh generation, door linking, exterior stitching | 🟡 | Works on the demo. The NVNM grid cell ordering and triangle winding rules are inferred from xEdit and need in-game confirmation, which is why the grid divisor defaults to 1. Cover data isn't generated. |
| Pre-release check, conflict report, BSA / ZIP packing | 🟡 | Checks run on your plugin's own records. Floating or sunk items are only checked for loose items (misc items, weapons, books…). Packing includes only loose files your records use (meshes plus the textures inside them, scripts, FaceGen, voice, SEQ and strings). The BSA is written in the game's format but hasn't been loaded by the real game here; files in other mods' archives are never packed. |
| World tools (paint, paths, arrays, drop, kit snapping, lighting pass, moods, clutter, room builder, linked doors) | 🟡 | They use the cell's real geometry, so they work on any mesh. Some parts rely on guesses that need checking against vanilla content:<br>• clutter themes and the lighting pass find items by Editor ID keywords;<br>• kit pieces are assumed to have their long side on the X axis (there's a turn setting if not);<br>• a door's arrival point goes on the side with floor and open space.<br>The mood presets are hand-picked colours, not copied from vanilla lighting templates. |
| Navmesh manual editing | ✅ | Tab enters edit mode, with Blender-style select / box / all. You can draw triangles (click 3 points, snapping to existing vertices, continuing as a strip), move vertices with G and X/Y/Z axis locks, delete triangles, and set the preferred / water / no-large-creatures flags. Edge links inside the mesh and the search grid are rebuilt after each edit. |
| Character creator and FaceGen | 🟡 | FaceGen (head mesh + face tint) is generated without the CK, and **checked against the CK's own FaceGen for vanilla characters** using the real Skyrim SE masters and archives (`tes5 face-compare`). On a sample of about 150 characters:<br>• **Identical:** file layout (a `BSFadeNode` named after the file, the bones, then a `BSFaceGenNiNodeSkinned` node with the shapes), shape types, vertex counts, skinning blocks, shader flags, hair colour (twice the hair colour form's value, the race default when the character has none) and scar skin tint.<br>• **Vertex positions:** within 0.2 units (about 3 mm), almost all within 0.05. Beards are about 0.1 off, and even a free best fit can't do better there, so the CK does something extra on beards.<br>• **Tint:** within 1–4/255 on average. Written like the CK's: BC3 with mipmaps down to 2×2 (re-encoding vanilla tints changes them by under 0.1/255 on average).<br>Recovered from the CK's output (fits exact to float precision):<br>• the slider ↔ morph table, including six names or directions that were wrong before;<br>• the race's own head shape (a morph named after the race, or its "morph race");<br>• weight (SkinnyMorph at 1 − weight/100, which also moves hair);<br>• the nose, eye and mouth presets (NoseType*n* etc.);<br>• the full vampire morph on vampire races;<br>• the race's default head, mouth and eyes for characters that don't list them;<br>• which texture-set slots the CK copies for each shader type.<br>Still differing from the vanilla files: some face texture paths (vanilla characters are themselves inconsistent), bone order, and part order for a few characters (both make no difference to the game). Characters that take their traits from a template (Use Traits) get no face files, as in vanilla (none of Skyrim.esm's 2,486 such characters has any); the creator points to the template. **No generated face has been loaded in the game yet.** Region shaping finds features from the vanilla chargen morphs (ears from the head's geometry). Extended sliders, extra morphs and region shapes are kept in `TES5EnvEditor/<plugin>.faces.json` next to the plugin (with undo); the baked face files keep them even if only the .esp is shared. The preview uses the bind pose of skinned heads and shows the head's texture times the face tint (an approximation of the game's face shader). |
| Body shaping (BodySlide sets, presets, build) | 🟡 | Reads slider sets (`.osp`), presets (`.xml`) and morph data (`.osd`, and old `.bsd` files), shapes the source mesh and writes the `_0` / `_1` meshes the way BodySlide does, moving only vertices (skinning, partitions, normals and tangents are kept or turned with the surface). **Tested only on the synthetic demo set; no real CBBE / UNP / 3BA set has been loaded.** The `.osd` layout and the `.osp` attribute names (`small`, `big`, `default`, `invert`, `local`) were written from memory of BodySlide's files and need checking against real ones. Not done: conversion references and zaps (sliders that hide vertices), set groups, the outfit/clothing side of Outfit Studio, body textures in the preview, and putting built meshes into the Release pack (they aren't referenced by a record, so the packer doesn't see them yet). |
| Quests: stages, objectives, aliases, fragments | ✅ | Alias fill types beyond unique actor, specific reference and location must be set in the properties panel. |
| Dialogue: topics, responses, conditions, begin/end scripts, voice names | ✅ | Scenes (SCEN) and packages (PACK) have typed schemas for what this editor writes; vanilla records with unusual layouts still show as raw fields. The voice-file truncation rule matches community documentation and should be confirmed. |
| Quest map (stages connected by what advances them) | ✅ | Connections are stored as ordinary dialogue, alias scripts and stage fragments, so the CK and xEdit see normal data. Stage changes made by hand-written scripts are only shown when they're a literal `SetStage(N)`. |
| Gestures in dialogue and at quest stages | 🟡 | The list of common gestures uses vanilla idle names (IdleWave, IdlePointClose, IdleApplaud2, …) that should be checked in game. A gesture uses PlayIdle when the IDLE form exists in the load order, and Debug.SendAnimationEvent otherwise. A gesture at a stage plays only if the character is loaded nearby. |
| Dialogue check | ✅ | The thresholds (80 characters for player lines, 150 for responses) are guidelines, not engine limits. "Still chosen after it moved the quest on" only counts a GetStage == N condition. |
| New places from a plan (copied layout, linked door, navmesh) | 🟡 | The layout is copied from a winning interior: statics, furniture, lights, clutter and markers, with links between copied objects (rooms, portals, multibounds) pointing at the copies. Characters, objects a quest turns on or off (initially disabled or with an enable parent), scripts, ownership and location data are left out. The copied layout's other load doors lead nowhere until linked. The new door goes against a wall found by ray casts (tall, clear, floor in front, away from other doors); outdoors it stands near the middle of the cell, to be moved by hand. Not checked in game, and vanilla room-bound and portal setups after copying haven't been checked. |
| Choices, endings and failure (from a plan) | 🟡 | A remembered choice is a Short global per quest (`<Quest>Chose<Name>`), set by the line's end script and checked with GetGlobalValue. Fail-on-death is a run-once death trigger on the character's quest alias, guarded so it does nothing once an ending or the fail stage was reached. A time limit is a small script on the quest (OnUpdateGameTime), registered from the start stage with RegisterForSingleUpdateGameTime; one per quest. Not compiled with the CK compiler or played in game yet. |
| How quests start (from a plan) | 🟡 | Entering a place, reading, picking up or using an object put a run-once trigger on a placed object (a hidden marker for places) that calls Start() on the quest, so it works while the quest isn't running. "After another quest" adds a Start() line to that quest's stage script, so it only works for quests in your own plugin (a vanilla quest's script would have to be rewritten). Items inside containers can't start a quest. The Story Manager (quests started by game events such as a courier delivery) isn't used yet. Not tried in game. |
| Events at quest stages (from a plan) | 🟡 | Enemies appear with PlaceActorAtMe, hostility uses relationship rank, aggression and StartCombat, fades use FadeOutGame, sounds and weather need SNDR / WTHR records in the load order. The generated stage scripts haven't been compiled with the Creation Kit compiler or played through in game yet. Enemies that appear can't be targets of a later "kill them" step yet. |
| Journal & objective writer | ✅ | Template drafts use the first step out of each stage; when a stage has several ways forward, edit the draft or ask Claude. |
| Routines (AI packages from templates) | 🟡 | Packages are made from the load order's Sandbox / Sleep / Eat / Travel / Follow / ForceGreet templates. The template's data inputs are copied, and the place (in a cell, or near the editor location), target (the player) or topic is filled in, with hours and stage conditions. The layout follows xEdit and is fully typed, but packages haven't been loaded in the CK or the game yet. The demo's templates are synthetic stand-ins. Escort (follow plus travel) and patrols aren't offered yet. |
| Visual triggers and templates | 🟡 | Generates Papyrus with a marker line so it can be read back; hand edits to a generated script are overwritten the next time its triggers are saved in the visual editor. Compiles cleanly with the built-in checker, but in-game behaviour of every action hasn't been tried. |
| Dialogue graph and screenplay import | ✅ | Speakers are matched by NPC name or Editor ID. |
| Updating a quest from a revised plan | ✅ | A record of what each build made is kept next to the plugin (TES5EnvEditor/<plugin>.plans.json) and follows undo/redo. Quests not built from a plan are read back from their data; their dialogue isn't replaced or removed by an update. Characters removed from a plan are left in the plugin, and a changed spot doesn't move someone already placed. |
| Greetings, chatter, scenes, conditions in scripts | 🟡 | Greetings and chatter use the quest's Hello (HELO) and Idle (IDLE) topics, and conditions are standard CK functions run on the player. Scenes are written as SCEN records following xEdit's layout (one phase per turn, actors as quest aliases) and read back the same way, but haven't been opened in the CK or played in game yet. Forcegreets need an AI package and come with AI routines. Scenes aren't written back when dialogue is exported as a script. |
| Quest from writing (Claude plans, you check, it's built) | 🟡 | The planner and builder are tested with the demo data and a mocked API; real plans from Claude depend on the writing and should always be checked on the review screen. New characters are copied from the character the text names, or a same-sex, same-race one with a voice (its routine and factions are removed). Hair, beard, eyes, scars and hair colour are picked by matching words to head-part and colour names, so results depend on how mods name them; the face shape is random. Changing an existing character from another plugin overrides it (a conflict with other mods that change them); changed faces get new face files when you save. Clothing must already exist in the load order (new pieces are copies of existing ones with a new name). New places are empty interiors. Placement casts rays against the cell's geometry: characters go on open floor at the load doors' level, or next to the object a spot names (matched by words in its name), and items go on tables or named furniture. Items "in" a container go into a copy of the container's base given to that one container, and the quest creates the item there (Create Reference to Object, In). Items the player must pick up or read have to start in a place; items held by a character move only through dialogue. The load-order summary sent to Claude lists up to 300 characters and interiors, your plugin's first. |

| SEQ files | 🟡 | Generated for start-game-enabled quests that own dialogue. The exact inclusion criteria should be confirmed against the CK. |

| Compiling scripts | 🟡 | Drives PapyrusCompiler.exe or Caprica. Tested with a fake runner only, since no compiler is available in CI. |
| Precombines/previs, LOD generation, Havok collision authoring, lip-sync generation | ❌ | Out of scope for now; use the CK or dedicated tools. |
| Items and Magic workspaces | ✅ | Categories, summaries and simple editors for items, crafting, loot lists, spells, effects, enchantments, shouts and perks; every field remains under "Show every field". Perk entry point names and some flag names follow xEdit and the CK wiki; the condition tab count per entry point is learned from the load order's perks (1 for entry points no vanilla perk uses). |
| Packaging (Windows installer) | 🟡 | Every pull request builds a Windows installer and a portable exe, and each new version on `main` is published as a GitHub release with both. The exes aren't code-signed yet, so Windows SmartScreen warns on first launch. No auto-update. |

## Performance at Skyrim.esm scale

`npm run bench` generates a synthetic master with about 915k records and groups (65 MB) and times the editor's operations. Typical results in the development container:

| Operation | Time |
| --- | --- |
| Load the plugin | ~0.7 s |
| Build lookup indexes once after loading | ~1.7 s |
| Search a record type (each keystroke) | 20–50 ms |
| List all cells | ~60 ms |
| Open a cell's references | <5 ms |
| Edit, place, undo or save a small plugin | <5 ms each |
| List every record with no filter, sorted | ~0.6 s |

- Edits never rebuild the indexes: the plugin being edited is merged in at query time.
- Memory after loading is about 0.5 GB of heap.
- The real Skyrim.esm is about 4× larger on disk, mostly because of compressed records, so expect parsing to take a few seconds. This hasn't been measured with the real file.

## Known uncertainties to verify in game

1. **Rotations:** the reference rotation convention (clockwise, applied Z·Y·X) is used consistently by the viewport, bounds and navmesh. It should still be checked by placing an asymmetric object and comparing with the CK.
2. **NVNM:** the grid ordering and the walkable-side winding.
3. ~~**Chargen TRIs**~~: confirmed against the CK's FaceGen for vanilla characters (see the character creator row).
4. **Voice files:** the file-name truncation rule.
5. **SEQ:** which quests must be listed in the SEQ file.
6. **Generated trigger scripts:** each trigger action in game (especially `movePlayerTo`, `lock` and `arrive` via OnCellAttach).
7. **MO2 launch:** the `moshortcut://` argument form and the profile switch.
8. **Scenes:** that generated SCEN records open in the CK and play in game (phases, actor behaviour flags, the missing VNAM).
9. **Routines:** that generated packages behave like CK-made ones from the same templates (data input values, schedule, alias packages).
10. **Gestures:** that the listed vanilla idle names play as expected from dialogue and stage scripts.
11. **Generated FaceGen:** the files now match the CK's in structure and shape, but still need loading in game: no dark-face bug, expressions and lip movement working, and region shaping looking right.
12. **Linked doors:** that arrival points land on the correct side for vanilla door meshes, and that the generated light forms (radius, flicker) look right in game.
